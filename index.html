画像1枚のために、何回書き出していますか

レスポンシブ対応をきちんとやろうとすると、画像1枚につきこれだけの作業が発生します。

  • 320 / 640 / 1024 / 1920 の4サイズに縮小する
  • WebP や AVIF に変換する
  • 古いブラウザ用に JPEG も残す
  • ファイル名を規則的に揃える
  • <picture> タグを手で書く

画像10枚なら、90ファイル。 1枚ずつ設定して書き出していたら、1時間では終わりません。

だから多くの現場で、srcset対応は「やったほうがいいのは分かっているが、後回し」になります。

ドラッグして、ダウンロードするだけ

必要なサイズと形式の組み合わせをすべて一度に書き出し、 書き出したファイルに対応する <picture> タグを生成します。 コピーして貼れば、それで終わりです。

<picture>
  <source type="image/webp" srcset="hero-320.webp 320w, hero-640.webp 640w, hero-1024.webp 1024w, hero-1920.webp 1920w" sizes="100vw">
  <img src="hero-1920.jpg" alt="" width="1920" height="1080" loading="lazy" decoding="async">
</picture>

できること

必要な組み合わせを、まとめて書き出す
サイズと形式を選ぶと、その全組み合わせを一度に生成します。既定値は 320 / 640 / 1024 / 1920 の WebP と、最大幅のJPEGフォールバック。
HTMLを書かなくていい
書き出したファイル名に対応した <picture> タグを生成します。ボタン1つでコピーできます。
寸法だけでなく、容量も落とす
サイズを縮めるだけではなく、圧縮品質を指定して再エンコードします。スマホで撮った4MBの写真が、数百KBになります。
位置情報を自動で削除
写真に埋め込まれた撮影場所などのEXIF情報は、書き出し時に取り除かれます。公開した画像から撮影場所が分かってしまう事故を防げます。
どれだけ軽くなったか見える
処理前後のファイルサイズを並べて表示します。削減率もそのまま出ます。
画像はどこにも送信されません
すべての処理がブラウザの中で完結します。サーバーへのアップロードは一切ありません。制作中の画像でも安心して使えます。

使い方

  1. 画像をドラッグ＆ドロップ（複数まとめて可）
  2. 設定を確認（そのままでよければ何も触らなくて構いません）
  3. ZIPでダウンロードし、HTMLをコピー

よくある質問

本当に無料ですか
はい。会員登録も不要です。
画像がどこかに送信されることはありませんか
ありません。すべてブラウザ内で処理しています。開発者ツールのネットワークタブを開けば、画像が送信されていないことをご自分で確認できます。
AVIFには対応していますか
設定でAVIFにチェックを入れると追加されます。最も軽くなりますが、初回のみ変換プログラム（約3.5MB）の読み込みが必要で、書き出しに1枚あたり数秒かかるため、既定ではオフにしています。
AVIFに対応していないブラウザではどうなりますか
生成される <picture> タグは、AVIF → WebP → JPEG の順にフォールバックします。対応していないブラウザは自動的に次の形式を読み込みます。
何枚まで処理できますか
一度に50枚までを推奨しています。それ以上でも警告を出したうえで続行できますが、お使いのPCの性能により時間がかかります。
画質は落ちませんか
圧縮品質を指定できます。既定値は、目視で劣化が分かりにくく、かつ十分に軽くなる設定にしています。

すべての処理はあなたのブラウザの中で完結します。開発者ツールのネットワークタブで、画像が送信されていないことを確認できます。
